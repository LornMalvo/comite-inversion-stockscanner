### 2. Veredicto de Desarrollo (StockScanner)

1. **Fix del hallazgo #34 (Media, prioridad de mantenimiento).** En `ui_vistas_rastreador.py::_rastrear()`, precalcular las posiciones abiertas una sola vez antes del bucle de rastreo (mismo patrón que `tarea_rastreo.py::_posiciones()`) y pasarlas a `datos_analisis.analizar()`:

2. **Diseño del monitor automático de condiciones de watchlist/reconsideración (prioridad alta, nueva funcionalidad).** Con 117+ tickers acumulados en `empresas_analizadas.md`, cada uno con una condición textual de reconsideración, el valor de que StockScanner las evalúe automáticamente cada noche es ya significativo. Pseudocódigo de diseño:
```python
# Nueva tabla en Supabase: watchlist_condiciones
# (ticker, tipo: 'roic_min'|'precio_cruce'|'rs_positiva'|'upside_min'|'otro', umbral, texto, sesion_origen)

def evaluar_condiciones_watchlist(analisis_cron: dict) -> list[Alerta]:
    alertas = []
    for cond in db_supabase.listar_condiciones_watchlist():
        dato = analisis_cron.get(cond.ticker)
        if dato is None:
            continue
        if cond.tipo == "roic_min" and dato.roic is not None and dato.roic >= cond.umbral:
            alertas.append(Alerta(cond.ticker, f"{cond.ticker}: ROIC alcanzó {dato.roic:.1%}, condición cumplida: {cond.texto}"))
        elif cond.tipo == "precio_cruce" and dato.precio is not None and dato.precio >= cond.umbral:
            alertas.append(Alerta(cond.ticker, f"{cond.ticker}: precio cruzó {cond.umbral}, condición cumplida: {cond.texto}"))
        # ... resto de tipos
    return alertas
```
   Integrarlo en `tarea_rastreo.py` junto al resto de tipos de evento de `core_alertas.py`, reutilizando el canal de Telegram ya existente.

def sincronizar_veredicto(ticker: str, plan_entrada: str, stop_tecnico: float,
                           stop_fundamental: str, sesion: str) -> bool:
